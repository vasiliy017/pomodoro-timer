## Findings

### R1 — [stage-1] A double-click on Pause or Resume toggles the phase twice — **Fix now**

- **Where:** `src/renderer/src/hooks/useTimerState.ts:79-81`, `src/renderer/src/screens/TimerScreen.tsx:132-142`. AC-02; ADR-0008.
- **Problem:**
  - `send()` takes the revision the hook holds at click time.
  - The IPC round trip finishes inside a double-click interval, and the swapped button (Pause → Resume) sits under the pointer, so the second click lands as a valid new command.
  - Reproduced against the built app: a double-click on Pause takes revision 1 → 3 and ends running; a double-click on Resume takes 2 → 4 and ends paused.
  - The test-plan row "User double-clicks Start in the real window" (e2e-through-UI) was never written.
- **Resolution:** ignore repeat clicks (`event.detail > 1`) on the control buttons. Add the e2e test that double-clicks Start, Pause, Resume and Skip with a realistic gap.

### R2 — [stage-2 → AC-07 / AC-14] A command is applied to a running phase that is already due — **Fix now**

- **Where:** `src/shared/timer.ts:257-264` (the command branch), `:352`, `:362-368`. AC-07, AC-14, AC-05.
- **Problem:** `transition()` never settles an overdue running phase (`endsAt <= now`, or `sleptAt` still set) before judging a command.
  - (a) A focus session ends while the Mac sleeps, and Pause arrives before `resume`. The session is later counted, which breaks AC-14.
  - (b) Skip is handled a few ms after `endsAt`, before the deadline timeout fires. The session moves on uncounted, with no notice, notification or Dock bounce, which breaks AC-07 and AC-05.
  - The property test's counted check (`timer.property.test.ts:113-120`) only looks at the previous step's `sleptAt`, so it misses both cases.
- **Resolution:**
  - In the command branch, before `startNewDay`, settle an overdue running phase: a synthetic `wake` if `sleptAt !== null`, otherwise a `deadline` if `now >= endsAt`. Keep its notice and effects. The command is then stale and is ignored.
  - Add unit cases for (a) and (b).
  - Track "ended while asleep" across steps in the property test.

### R3 — [stage-1] The midnight new-day reset erases a waiting phase-end notice — **Fix now**

- **Where:** `src/shared/timer.ts:340-342` (via `applied()` at `:416`, which sets `notice: null`). AC-06 vs AC-15.
- **Problem:**
  - AC-06 keeps the notice "until the User's next command or the next phase end".
  - Say a phase ends at 23:58 with notifications blocked and the window closed. The midnight deadline then clears the notice.
  - The notice survives only when the phase end and the new day fall in the same transition (`:271-272`).
- **Resolution:** carry the existing notice through `startNewDay`, with a unit test.

### R4 — [stage-1] `isTimerCommand` accepts commands with extra fields — **Fix now**

- **Where:** `src/shared/timer.ts:194-200`. AC-02, contract row `test-plan.md:46`.
- **Problem:**
  - The test plan requires a command carrying extra fields (such as a time or phase) to be refused.
  - The guard accepts `{type:'start', revision:0, endsAt:…}`. Behaviour is not affected, since the rules ignore extra keys, but the contract row is untested and unmet.
- **Resolution:** reject unknown keys, and add the cases to `timer.test.ts`.

### R5 — [stage-1] AC-03 (one timer per macOS account) has no automated test — **Fix now**

- **Where:** `src/main/index.ts:46-50` (correct by construction); `test-plan.md:51`. AC-03.
- **Problem:**
  - The e2e row "two instances with separate user-data directories keep independent timers" was never written.
  - Verification check 13 covers a second launch in the *same* account, which is AC-13, not AC-03.
  - So AC-03 drops out of the chain at the test step.
- **Resolution:** launch two instances with different `--user-data-dir`. Start in A, and assert B stays at a ready focus session 1 of 4 with the cycle at 0.

### R6 — [stage-1] Two AC-13 e2e rows from the test plan are missing — **Fix now**

- **Where:** `e2e/timer.spec.ts` (absent); `src/main/index.ts:42`; `test-plan.md:89-90`. AC-13.
- **Problem:** two rows have no test.

  - "The next launch after a quit starts fresh".
- **Resolution:**

  - Add a quit-then-relaunch test that asserts a ready focus session 1 of 4 with the cycle at 0.

### R7 — [stage-1] The AC-12 e2e test covers only the confirm path — **Fix now**

- **Where:** `e2e/timer.spec.ts:115-121`; `test-plan.md:81`. AC-12.
- **Problem:** the test plan asks for Cancel first (phase and cycle unchanged), then Confirm. Cancel is exercised only in the component test with a mocked hook (`TimerScreen.test.tsx:227`).
- **Resolution:** add a Cancel step before Confirm, and assert that status and cycle are unchanged.

### R8 — [stage-1] The NFR e2e scenarios are thinner than the test plan, and AC-01 is partly asserted — **Fix now**

- **Where:** `e2e/boot.spec.ts:11-26`, `e2e/timer.spec.ts:103-180`; `test-plan.md:154-175`. Spec §6, AC-01.
- **Problem:**
  - The test plan asks for 3 cold launches, 5 consecutive phase ends and 10 clicks per control. Each scenario runs once.
  - After Start, the e2e test checks "Running" with a 60 s config. It never asserts the heading or the 25:00 start on the default config.
- **Resolution:** loop the scenarios as the test plan specifies, and add the AC-01 assertion on the default config right after Start.

### R9 — [stage-2] The sentence naming what a Restart cycle loses is written twice — **Fix now**

- **Where:** `src/renderer/src/screens/TimerScreen.tsx:53-67` (`lossText`) and `src/main/quit-guard.ts:47-68` (`lossMessage`). AC-12, AC-13.
- **Problem:**
  - The same pure function and phase-name map exist in two places.
  - AC-13 requires the quit dialog to name the loss "as Restart cycle does", and the two copies can drift silently.
  - Only `lossMessage` has unit tests.
- **Resolution:** move one pure function next to `restartLoss` in `src/shared/timer.ts`, import it in main and the renderer, and move its tests alongside.

### R10 — [stage-2] Keyboard focus is lost each time Start/Resume and Pause swap — **Fix now**

- **Where:** `src/renderer/src/screens/TimerScreen.tsx:134-136`. AC: n/a (accessibility).
- **Problem:**
  - With `key={name}`, pressing Start unmounts the focused button, so focus falls to `<body>`.
  - A keyboard user can't press Space again to pause.
- **Resolution:**
  - Give the primary control slot one stable key, so the same DOM button keeps focus while its label changes.
  - Add a component test that focus stays on the button.
  - This goes together with R1: repeat clicks are ignored, so a stable button doesn't bring back the double-toggle.

### R11 — [stage-2] The control-latency e2e test can stop its clock on a countdown tick — **Fix now**

- **Where:** `e2e/timer.spec.ts:85-89`. Spec §6 (control responsiveness).
- **Problem:**
  - `timeClick` stops on the first change to `body.innerText`.
  - For a running phase a countdown tick can come first, so the 100 ms check can under-measure.
- **Resolution:** stop the clock on the command's expected effect (the status text or heading equals the target).

### R12 — [stage-2] The Restart-cycle dialog doesn't link its loss text — **Fix now**

- **Where:** `src/renderer/src/components/ui/Dialog.tsx:47-50, 67`. AC-12 (accessibility).
- **Problem:**
  - Only `aria-labelledby` is set.
  - Focus moves to Cancel, so a screen reader announces the title and "Cancel" without the sentence naming what will be lost.
- **Resolution:** add a second `useId()` for the body and `aria-describedby` on the `<dialog>`, with an assertion in `Dialog.test.tsx`.

### R13 — [stage-2] Once set, the OS-initiated-quit flag never resets — **Fix now**

- **Where:** `src/main/quit-guard.ts:20, 41-43`. AC-13.
- **Problem:**
  - A logout or shutdown can be cancelled after powerMonitor's `shutdown` fired, for example when another app refuses to quit.
  - `osInitiated` then stays true, and every later ⌘Q quits without asking, even with progress at stake.
- **Resolution:** clear the flag after the quit it covered (for example, a short timeout after `shutdown`), with a quit-guard unit test.

### R14 — [stage-2] Hide-on-close doesn't handle a full-screen window — **Fix now**

- **Where:** `src/main/window.ts:17-36`. AC-13, ADR-0009.
- **Problem:** the window is full-screenable by default. On macOS, `hide()` on a full-screen BrowserWindow leaves an empty black Space.
- **Resolution:** set `fullscreenable: false` on the 420×560 timer window, with a `window.test.ts` assertion.
